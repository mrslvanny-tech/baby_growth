# 小芽成长 V1 iCloud 同步与产品边界设计

日期：2026-05-31

## 1. 目标

V1 增加 iCloud 同步能力，让用户在自己的 Apple 设备之间保留宝宝资料和成长记录。

本能力服务于：

```text
不丢记录
换机可恢复
iPhone / iPad 可看到同一份成长记录
```

V1 不把 iCloud 做成家庭协作、账号系统或照片云盘。

## 2. 已确认产品决策

### 2.1 同步对象

V1 同步文字和结构化数据：

- 宝宝资料：昵称、出生日期、头像标识、创建时间、更新时间。
- 成长记录：标题、日期、描述、分类、模板标识、视觉元素类型、创建时间、更新时间。
- 树成长进度：不单独存储，由成长记录数量实时计算。

V1 不同步图片：

- `mediaLocalIdentifiers` 暂时保留。
- 如果某条记录未来绑定了本机相册图片，另一台设备不保证能显示同一张图片。
- 图片同步进入 V1.1 设计。

### 2.2 同步范围

V1 只支持用户自己的设备同步：

- 使用用户自己的 iCloud 私有数据库。
- 不做家人共享。
- 不做多人共同编辑。
- 不做 App 内账号登录。

### 2.3 iCloud 不可用时

如果用户没有登录 iCloud，或关闭了小芽成长的 iCloud 权限：

- App 继续本地可用。
- 不阻断建档、记录、查看历史、生成纪念卡。
- 设置页显示 iCloud 状态和系统设置引导。

### 2.4 App 内开关

V1 不提供 App 内 iCloud 开关：

- 系统 iCloud 可用时，App 自动使用 iCloud 同步。
- 系统 iCloud 不可用时，App 使用本地存储。
- 设置页只展示状态，不让用户在 App 内切换本地/云端模式。

### 2.5 冲突规则

同一条数据在多设备被修改时，V1 采用“最后修改者覆盖”：

- 以 `updatedAt` 最新的数据为准。
- 新增记录不互相覆盖，因为每条记录有独立 `UUID`。
- V1 不做冲突弹窗。
- V1 不保留历史版本。

### 2.6 删除规则

V1 支持删除成长记录：

- 一台设备删除后，其他设备也同步删除。
- 删除前必须二次确认。
- 删除确认文案需要提示“会从使用 iCloud 的设备中移除”。
- V1 不做“最近删除”恢复机制。

## 3. 设置页 iCloud 区域

设置页需要新增明显的 iCloud 同步区域。

### 3.1 展示位置

建议放在宝宝信息之后、其他设置之前。

原因：

- iCloud 属于数据安全和设备同步能力。
- 用户找同步、备份、换机相关信息时，直觉会进入设置页。
- 不打扰首页核心记录流程。

### 3.2 状态文案

V1 至少支持以下状态：

| 状态 | 标题 | 说明 |
| --- | --- | --- |
| 可用 | iCloud 同步已开启 | 成长记录会保存在你的 iCloud，并在你的设备之间同步。 |
| 未登录 | iCloud 未登录 | 请在系统设置中登录 Apple ID，以便同步成长记录。 |
| 受限 | iCloud 暂不可用 | 请检查系统 iCloud 设置或网络状态。 |
| 本地 | 当前仅保存在本机 | 你仍然可以正常记录，开启 iCloud 后会同步。 |

### 3.3 操作入口

设置页可提供一个按钮：

```text
打开系统设置
```

点击后跳转系统设置。V1 不在 App 内尝试登录 Apple ID。

### 3.4 最近同步时间

V1 可以展示：

```text
最近更新：刚刚 / 今天 14:30 / 暂无同步记录
```

注意：这个文案表达“本机最近数据更新时间”即可，不承诺 CloudKit 已完成远端落库。

## 4. 技术方案方向

### 4.1 推荐架构

使用 SwiftData + CloudKit：

- 保留现有 SwiftData 数据模型。
- 为 `ModelConfiguration` 增加 CloudKit 支持。
- 配置 iCloud Capability。
- 使用私有 CloudKit Container。

当前入口：

- `App/XiaoyaGrowthApp/XiaoyaGrowthApp.swift`
- `App/Models/PersistentModels.swift`

### 4.2 Entitlements 和工程配置

需要新增或调整：

- iCloud Capability。
- CloudKit。
- iCloud Container，例如：

```text
iCloud.com.xiaoyagrowth.app
```

实际 Container ID 需要与 Apple Developer 后台和 Bundle ID 对齐。

### 4.3 模型要求

当前模型已经具备同步基础：

- `BabyProfile.id`
- `MilestoneRecord.id`
- `createdAt`
- `updatedAt`

实现前需要检查 SwiftData + CloudKit 约束：

- 字段类型必须 CloudKit 支持。
- 默认值必须稳定。
- 必填字段在历史数据迁移时不能造成启动失败。
- 数组字段如 `mediaLocalIdentifiers`、`moodTags` 需要确认 CloudKit 映射表现。

### 4.4 本地数据迁移

目标：

- 用户已有本地数据不能丢。
- 开启 iCloud 后，本地数据应进入同步容器。

实现时需要验证：

- 现有本地 SwiftData store 切换到 CloudKit 配置后的行为。
- 首次升级是否能保留旧数据。
- 如果不能自动保留，需要设计一次性迁移流程。

## 5. V1 产品边界

### 5.1 宝宝数量

V1 只支持一个宝宝：

- 首页只展示一个宝宝的一棵成长树。
- 设置页只编辑当前宝宝。
- 不做多宝宝切换。

多宝宝进入 V1.1 或之后版本。

### 5.2 商业化方向

分享卡是未来商业化核心：

- V1 先免费跑通分享闭环。
- 后续可扩展主题卡、高清导出、成长年册、打印纪念册。
- 商业化不能干扰“记录成长 -> 点亮叶片 -> 小树成长”的主链路。

### 5.3 35 条后的森林状态

V1 做轻量可见状态：

- 不做完整森林页。
- 首页可展示“已经长成 X 棵树，正在点亮第 Y 棵”。
- 主视觉仍然聚焦当前正在成长的树。

### 5.4 长期定位

主定位：

```text
私密宝宝成长纪念册
```

表达方式：

```text
轻游戏化成长树
```

暂时不走：

```text
宝宝发育评估 / 医学管理 / 焦虑型里程碑工具
```

## 6. 验收标准

### 6.1 iCloud 可用

- 首次创建宝宝资料后，数据可进入 iCloud 同步容器。
- 新增成长记录后，另一台同 Apple ID 设备可同步看到。
- 首页成长树数量与同步后的记录数量一致。
- 分享卡使用同步后的记录和树状态生成。

### 6.2 iCloud 不可用

- 未登录 iCloud 时 App 可正常启动。
- 用户可创建宝宝资料。
- 用户可新增成长记录。
- 设置页清楚提示 iCloud 未开启。
- 不出现白屏、崩溃或强制登录。

### 6.3 冲突

- 两台设备编辑同一条宝宝资料，以较新的 `updatedAt` 为准。
- 两台设备分别新增记录，最终都保留。
- V1 不弹出冲突解决弹窗。

### 6.4 删除

- 删除记录前出现确认弹窗。
- 确认删除后本机历史列表移除该记录。
- 同步后其他设备也移除该记录。
- 删除后首页树状态按剩余记录重新计算。

### 6.5 回归

- Onboarding 可完成。
- 首页可进入模板页。
- 记录保存后返回首页，树变化。
- 纪念卡可打开、分享、保存图片。
- 设置页展示态不出现日期滚轮，编辑态才出现日期滚轮。

## 7. 暂不实现

V1 不实现：

- 家庭共享。
- 多 Apple ID 共同编辑。
- App 内 iCloud 登录。
- App 内 iCloud 开关。
- 图片跨设备同步。
- 最近删除。
- 多宝宝。
- 完整森林页。
- 付费主题卡。

这些能力需要单独进入后续版本设计。
